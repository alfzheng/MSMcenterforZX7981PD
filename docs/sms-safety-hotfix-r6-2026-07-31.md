# 短信安全热修 r6 发布记录

日期：2026-07-31（Asia/Shanghai）

状态：已构建、安装并通过真机安全验收

## 1. 触发原因

r5 已在真机证明设备删除五层失败关闭有效，但守护进程重启后的首次 `summary`
调用仍通过 `req.defer()` 等待完整 SM/ME 扫描。目标机双存储冷扫描超过 ubus
客户端等待窗口，导致首轮验收超时；扫描完成后的重试可正常返回 37 条短信的
仅元数据摘要，服务和模组没有崩溃。

页面主列表使用的 `list` RPC 已采用非阻塞冷加载，本缺口位于 `summary` RPC。
为保证包版本与构建字节一一对应，不覆盖或重打同版本 r5，两个包的
`PKG_RELEASE` 提升为 6。

## 2. r6 变更

- 守护进程冷缓存下调用 `summary` 时只启动一个后台加载任务，并立即返回
  `ok:true,loaded:false,loading:true`；
- 冷加载响应不包含短信正文或号码，计数暂为 0，保留后端可用性、队列和存储
  元数据；
- 后台 SM/ME 扫描完成后，后续 `summary` 返回
  `loaded:true,loading:false` 和真实计数；
- r5 的删除安全门禁全部保留：能力为 false、兼容 RPC 固定失败、后端能力 false、
  ACL 无 delete、LuCI/CLI 无删除入口；
- 不改变发送幂等、缓存时长、模组协议、`usb0` 或移动数据配置。

## 3. 新增验收门禁

真实 daemon/ubus 假后端集成测试新增冷 `summary` 用例，并在重新启动的空缓存
进程上独立验证冷 `list`，避免同步假后端造成测试竞态。真机验收必须满足：

1. 重启服务后的首次 `summary` 在 ubus 客户端超时前返回
   `loaded:false,loading:true`；
2. 轮询完成后返回 37 条仅元数据摘要，SM/ME 使用量与 r5 安装前基线一致；
3. 固定不存在 ID 的旧 `delete` 调用返回 `DEVICE_DELETE_DISABLED`，调用前后
   计数、存储使用量和缓存时间不发生删除型变化；
4. APK、ACL、守护进程和 LuCI 负面断言全部通过；
5. `usb0` 地址、默认路由和 overlay 状态正常；
6. 不发送或删除真实短信。

## 4. 真机结果

- r6 三包在独立快照中通过 `apk verify`、`adbdump`、解包、LF 和删除负面断言，
  上传目标机后再次通过 SHA-256 和 `apk verify`；
- 首次冷 `summary` 在 0 秒内返回
  `loaded:false,loading:true`，最终一次干净验收的后台扫描在 32 秒完成；
- 完成摘要为 37 条，仅元数据计数为收件 28、发件 9；SM 为 40/50，ME 为
  21/50；
- 固定不存在 ID 的删除探针返回 `DEVICE_DELETE_DISABLED`，调用前后总数、
  SM/ME 使用量和 `cache_updated_at` 完全一致；
- 13 组真实 daemon/ubus 假基带集成测试全部通过，正式配置和服务在测试退出后
  自动恢复；
- ACL 仅允许 `send` 写方法，目标包内无公开后端删除调用、LuCI 删除方法或删除
  控件，脚本均为 LF；
- `usb0` 仍为 `10.65.179.52/24`，默认路由仍经 `10.65.179.1`，overlay
  仍为 45% 使用率；
- 全程未发送或删除真实短信。

安装时重启 `rpcd` 使原 LuCI 浏览器会话失效。目标机上的 LuCI 静态文件与 ACL
已经检查通过；重新登录后可补做纯视觉冒烟检查，不影响上述后端、安全和网络验收
结论。
