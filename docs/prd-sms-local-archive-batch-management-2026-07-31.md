# 短信中心本地归档、批量管理与分页 PRD

版本：0.2（对抗性审计修订稿）

日期：2026-07-31

关联产品：ZX7981PD LuCI 短信中心

关联主 PRD：`PRD.md` 1.4

审计状态：产品约束修订后可进入技术设计；阶段 C 在全部硬门禁通过前保持禁用

目标发布：阶段 A/B/C 分阶段确定，不以同一发布一次性开放全部破坏性能力

## 1. 背景

当前短信中心能够读取 `SM`（SIM 卡）与 `ME`（移动设备/模组）中的短信，但列表快照
只保存在守护进程内存中。守护进程重启后必须重新扫描模组，短信从 `SM/ME` 删除后也
没有插件侧副本。

ZX7981PD 现场完整读取 `SM/ME` 约需 23–44 秒。单条删除为了防止存储索引复用导致
误删，会先重新读取双存储，再执行物理删除并恢复默认存储。该同步操作可能超过 LuCI
RPC 的等待时间：目标机已经观察到后端记录 `delete_complete state=deleted`，但前端
仍显示 `SERVICE_UNAVAILABLE` 的假失败。

用户需要：

1. 将短信复制或安全移动到插件自己的持久存储。
2. 多选、选择当前页和选择全部筛选结果。
3. 批量复制、移动和删除。
4. 分页显示，并可选择每页数量，默认 10 条。
5. 长操作有可查询的真实状态，不再用 `SERVICE_UNAVAILABLE` 表示未知结果。

## 2. 名词与产品边界

| 名词 | 定义 |
|---|---|
| `SM` | SIM 卡短信存储 |
| `ME` | 5G 模组/移动设备短信存储 |
| `LOCAL` | 本插件管理的本地持久短信归档 |
| 短信中心 | 本产品及其 `LOCAL` 归档，不是运营商 SMSC 号码或网络侧短信中心 |
| 逻辑短信 | UI 中的一条短信；可能对应一个或多个物理 PDU 分片 |
| 物理位置 | `SM/ME` 中具体的存储区与索引 |
| 扫描 epoch | 一段可连续证明来源身份的随机标识；守护进程启动、模组重置或来源连续性丢失时更换 |
| 来源 generation | 同一扫描 epoch 内物理位置的单调代次；观察到清空、替换或本系统发起写操作时递增 |
| 复制 | 持久写入 `LOCAL`，保留 `SM/ME` 原记录 |
| 移动 | 先持久写入并校验 `LOCAL`，再删除 `SM/ME` 原记录 |
| 批量任务 | 后台执行、可查询状态、可恢复和可审计的复制/移动/删除操作 |

本 PRD 不改变运营商 SMSC 配置，不增加任意 AT 命令入口，也不允许浏览器直接访问
`lteat`。

## 3. 产品目标

### 3.1 目标

- 页面优先从 `LOCAL` 与现有内存快照生成列表，不因模组冷扫描阻塞首屏。
- 管理员可以安全批量复制、移动和删除逻辑短信。
- 所有可能超过 RPC 等待时间的写操作都转为后台任务。
- 移动必须满足“本地归档已持久化并校验成功”后才允许删除物理记录。
- 分页、筛选和排序在大量本地短信下仍保持稳定、可重复。
- 超时、重启、分片部分失败和客户端断线不得造成静默重复删除。

### 3.2 非目标

- 不自动把所有新短信从 `SM/ME` 删除。
- 不提供无确认的“一键清空全部存储”。
- 不把 `LOCAL` 当作运营商投递成功凭证。
- 不在本阶段提供云同步、邮件转发、Webhook 或多设备共享。
- 不承诺插件停机期间突破 `SM/ME` 的物理容量限制。
- 不在日志、任务摘要或诊断包中记录短信正文、完整号码或完整 PDU。

## 4. 用户故事

### US-01 本地保留

管理员选择一条或多条 `SM/ME` 短信，点击“复制到短信中心”，归档成功后仍可在
原存储看到短信。

### US-02 安全释放模组容量

管理员选择短信并点击“移动到短信中心”。系统先归档、落盘和校验，再删除全部关联的
物理分片。归档失败时不得触碰 `SM/ME`。

### US-03 批量清理

管理员按收件箱、发件箱、来源、日期或关键词筛选，选择当前页或全部筛选结果，提交
批量删除任务，并看到逐项进度与部分失败原因。

### US-04 大量历史浏览

管理员浏览本地归档，默认每页 10 条，可以切换 20、50 或 100 条，并在翻页后保持
筛选、排序和每页数量设置。

### US-05 超时后确认真实结果

浏览器断线或 RPC 超时后，管理员通过提交前保存的请求 ID 找回任务并继续查询状态。
系统不得把结果未知显示为明确失败，也不得自动重复移动或删除。

## 5. 信息架构

### 5.1 统一列表

列表支持以下维度：

- 信箱：收件箱、发件箱、全部。
- 来源：全部、`SM`、`ME`、`LOCAL`。
- 状态：设备中、本地已归档、设备与本地均存在、仅本地、处理中、部分失败。
- 时间范围：全部、自定义起止日期。
- 号码/关键词：仅在管理员显式搜索时查询，不写入日志。
- 排序：时间降序（默认）、时间升序、首次归档时间。

列表行必须显示：

- 选择框；
- 时间；
- 脱敏号码；
- 正文摘要；
- 方向与状态；
- 来源标签（`SM`、`ME`、`LOCAL`，可多选）；
- 分片完整度；
- 当前批量任务状态；
- 单条详情与单条操作入口。

### 5.2 分页

- 默认每页 10 条。
- 可选 10、20、50、100 条。
- 每页数量保存在浏览器本地设置中；非法或过期值回退到 10。
- 后端使用稳定 cursor 分页，不使用仅依赖可变数组下标的分页。
- 默认排序键为 `timestamp DESC, archive_id DESC`；无时间短信使用
  `first_seen_at DESC, archive_id DESC`。
- 响应返回 `items`、`next_cursor`、`prev_cursor`、`page_size`、
  `filtered_count` 和 `snapshot_version`。
- 数据变化导致 cursor 失效时返回 `CURSOR_STALE`，前端回到第一页并保留筛选条件。

### 5.3 选择模型

- 行复选框选择单条逻辑短信。
- 表头复选框只选择或取消当前页。
- 当前页全选后显示“已选择本页 N 条；选择全部 M 条筛选结果”。
- “选择全部筛选结果”必须生成带过期时间和 `snapshot_version` 的服务端
  `selection_token`，不能把无限 ID 列表放进浏览器或 RPC 请求。
- `selection_prepare` 必须原子物化确认时刻的不可变成员集合；每项至少包含
  `source`、稳定 ID、物理位置、扫描 epoch、来源 generation、完整 PDU SHA-256
  和消息指纹。
- 当前页勾选、单条操作和“全部筛选结果”必须经过同一个 `selection_prepare`
  线性化点；不允许 `batch_create` 直接接受未物化的裸 ID。
- 执行任务时不得重新运行筛选，也不得纳入 token 创建后新到达或新匹配的短信。
- 选择全部后取消单项时，前端提交受限 `exclude_ids`；服务端重新计算最终数量、
  来源分布和 `selection_digest`，并要求用户按最终摘要确认。
- token 必须绑定调用主体、操作类型、删除作用域、最终成员集合摘要和过期时间。
- token 过期、排除项无效或任一成员身份变化时，任务创建整体失败且零写操作。
  与成员无关的新短信到达或全局 `snapshot_version` 增长不使已物化集合失效。
- 守护进程重启、模组重置、默认存储恢复失败或无法证明来源连续性时必须更换扫描
  epoch；旧 epoch 的 token 和尚未开始物理删除的项目全部失败关闭并要求重新选择。
- 改变筛选条件后，旧 `selection_token` 立即失效。
- 操作栏显示总选择数以及 `SM/ME/LOCAL` 分布。
- 长短信按一条逻辑短信选择；禁止只选择其中一个已安全拼接的物理分片。
- `SM/ME` 尚在加载、快照过期或任一来源读取不完整时，禁止创建涉及设备删除的
  全选 token。

## 6. 功能需求

### FR-101 本地持久归档

- `LOCAL` 必须在设备重启和守护进程重启后保留。
- 归档记录至少包含：
  - `archive_id`；
  - 当前逻辑消息指纹及算法版本；
  - 每个物理分片的原始 PDU SHA-256、物理位置、扫描 epoch、来源 generation
    与首次发现时间；
  - 方向、号码、正文、时间、编码与分片完整度；
  - 原始来源、原始物理位置和首次/最近发现时间；
  - 归档时间、更新时间和删除状态；
  - 当前是否仍存在于 `SM/ME`；
  - `archive_quality`、`lossless_archivable` 与不可移动原因。
- 对来自 `SM/ME` 的记录，后端必须在受限内存中对每个完整原始 PDU 计算 SHA-256，
  并将摘要作为来源实例身份的一部分。
- `archive_store_raw_pdu=1` 时，普通复制逐字节保存每个原始 PDU；显式关闭该配置
  时，复制只保存解析记录并标记 `archive_quality:rendered`。任何移动都必须在
  删除设备记录前逐字节保存每个原始 PDU，以保存后的 SHA-256 与来源摘要校验一致，
  并标记 `archive_quality:lossless`。
- 只有正文、号码、方向、编码、状态、时间和全部物理分片都可无损表示，分片完整、
  关联可信、来源读取完整，且每个原始 PDU 已通过耐久化屏障和独立读回校验时，
  `lossless_archivable` 才能为 `true`。
- 原始 PDU 只允许存在于 root 专用数据库和一致性备份中，不得由普通分页、
  `archive_get`、任务状态、日志或诊断接口返回。关闭原始 PDU 保全配置时，复制仍
  可用，但所有归档均为 `lossless_archivable:false`，移动和全部设备删除入口必须
  禁用。
- 8-bit/未知编码、解码失败、`complete:false`、分片总数冲突、重复分片序号、
  关联歧义或来源读取不完整的记录，只允许复制为受限的不完整归档，禁止移动和
  逻辑级设备删除。
- 对同一来源实例身份和归档内容摘要重复复制必须幂等返回既有 `archive_id`。
- 同一索引被模组复用且指纹变化时必须创建新归档记录，不能覆盖历史短信。
- 仅现有 64 位非密码学消息指纹不得承担移动或设备删除的安全判定。
- 不跨 `SM/ME` 仅按正文自动合并，以保持现有防误删边界。
- 数据文件权限为 `0600`，目录仅 root 可访问。
- 持久路径必须可配置；不得默认使用重启即清空的 `/tmp` 或 `/var`。
- ZX7981PD 默认路径为 `/root/modem-sms/archive.sqlite3`；目录权限为 `0700`。
  改用外接持久存储必须经过显式迁移，不得静默创建第二个空数据库。
- 发布前必须在目标机确认 overlay 可用空间、写放大、掉电恢复和 sysupgrade 行为。
- 本地归档达到容量上限时停止新增并返回 `ARCHIVE_FULL`；默认不自动删除旧短信。

### FR-102 复制到短信中心

- 复制仅适用于当前仍存在于 `SM/ME` 的逻辑短信。
- 任务执行时重新确认扫描 epoch、来源 generation、物理位置、原始 PDU SHA-256
  和消息指纹；任一不匹配返回 `MESSAGE_CHANGED`。
- 不完整或不可无损表示的短信允许复制，但必须显示
  `archive_quality:incomplete`，且不得被后续移动任务复用。
- 本地写入必须经过事务提交、耐久化屏障和独立读回校验后才返回成功。
- 已归档记录返回 `already_archived:true`，不创建重复正文。
- 复制不得删除或修改任何 `SM/ME` 物理位置。

### FR-103 移动到短信中心

- 移动采用两阶段流程：
  1. 归档阶段：写入 `LOCAL`、持久化并校验；
  2. 删除阶段：重新读取相关存储，验证来源实例身份并逐个删除物理分片。
- 仅 `lossless_archivable:true` 的记录允许移动。
- 归档阶段失败时，删除阶段绝不能开始。
- 删除阶段失败时保留本地归档，并将任务标记为 `partial`、`unknown` 或 `failed`；
  不自动重试结果未知的删除。
- 多分片短信只有在所有分片归档完成后才可开始物理删除。
- 活动移动任务必须持久 pin 其 `archive_id`。永久清理、自动清理、数据库迁移和
  本地删除对被 pin 的记录返回 `ARCHIVE_IN_USE`。
- 每个物理删除前，必须用同一本地事务重新确认归档存在、校验通过、仍被 pin，
  且没有进入回收站或清理流程，并持久化删除意图；事务提交完成后，在仍受全局
  模组串行临界区保护且不释放 pin 的前提下紧邻调用物理删除。
- 任务中断后只允许进行只读核验；不能证明结果时保持 `unknown`，不得再次调用删除。
- 移动完成后列表记录保留，来源更新为 `LOCAL`，并显示原来源。
- 默认存储恢复失败但物理删除已完成时，任务返回
  `completed_with_warning`，不得显示为“未删除”。

### FR-104 删除

删除必须明确作用域：

| 作用域 | 行为 |
|---|---|
| 仅设备 | 确保存在已校验的无损 `LOCAL` 安全副本后删除 `SM/ME`，保留 `LOCAL` |
| 仅本地 | 移入本地回收站，不触碰 `SM/ME` |
| 设备和本地 | 确保无损安全副本后删除设备记录；全部确认成功后才将本地记录移入回收站 |

- 对同时存在于设备和本地的记录，确认框不得预选“设备和本地”。
- 所有设备删除都必须具备可写、可耐久提交且健康的任务/归档状态库，并先复用或
  创建经过独立读回校验的无损本地安全副本；任一条件不满足时返回
  `STATE_STORE_UNAVAILABLE` 或 `ARCHIVE_NOT_LOSSLESS`，设备零删除。
- 删除设备短信前必须重新读取目标存储，并验证扫描 epoch、来源 generation、
  物理位置、完整原始 PDU SHA-256 和消息指纹。
- `lossless_archivable:false` 的逻辑短信禁止普通移动和逻辑级设备删除；本版本
  不提供绕过该门槛的“高级物理分片删除”。
- 多分片短信逐分片记录结果；部分删除必须返回成功数、失败位置和结果未知位置。
- 移动、“仅设备”和“设备和本地”任务都必须在首个物理删除前耐久 pin 安全副本；
  pin 获取与清理/迁移判定在同一数据库事务中互斥。
- 任务存在任一 `unknown` 物理结果时不得释放 pin，也不得把本地记录移入回收站；
  只有经过备份、只读核验和审计记录的人工核销才能解除该 pin。
- 本地删除默认进入回收站，保留 30 天；永久删除需要再次确认。
- 回收站保留天数可配置为 1–365 天；设为 0 表示禁用自动清理，不表示立即删除。
- 自动清理和永久删除必须跳过所有被活动任务 pin 的记录。
- 任何超时都不得自动重复删除。

### FR-105 异步批量任务

复制、移动和设备删除必须通过后台任务执行。

任务状态：

`accepted → validating → archiving → deleting → verifying → completed`

异常终态：

- `completed_with_warning`
- `partial`
- `failed`
- `unknown`
- `cancelled`

要求：

- 创建任务必须在 1 秒内返回 `job_id`，不等待模组操作完成。
- 客户端必须在提交前持久保存服务端当前 `request_namespace` 和调用方生成的
  `request_id`；即使创建响应丢失，也能使用二者找回任务。
- 幂等唯一键为 `(authenticated_principal, request_namespace, request_id)`；
  `batch_lookup`、`batch_status` 和 `batch_cancel` 均必须验证同一认证主体，不得
  泄露或控制其他主体的任务。
- 服务端必须从已解析、已授权的权威参数进行规范序列化并独立计算
  `request_digest`，不得信任客户端提交的摘要。服务端在入队和返回响应前必须
  持久化唯一键、`job_id` 与摘要；摘要覆盖操作类型、作用域、确认码、最终不可变
  选择集合、排除集合及其他影响结果的参数。
- 相同幂等唯一键和服务端摘要重复提交返回原任务；同一唯一键对应不同摘要返回
  `REQUEST_ID_CONFLICT`，且零写操作。
- 状态包含总数、待处理、已处理、成功、跳过、失败、未知、取消和当前阶段。
- 状态必须提供安全错误码，不返回短信正文或完整号码。
- 任务开始物理删除前允许取消；进入删除阶段后只能在逻辑短信边界停止尚未开始的
  项目，不得在一条多分片短信删除到一半时因取消而主动中断。
- 守护进程重启后恢复任务元数据。对结果未知的物理删除不得自动重做。
- 同一时间最多执行一个访问模组的 SMS 操作；纯本地分页和读取不应被阻塞。
- 每个物理位置的持久状态至少为
  `prepared → delete_intent_durable → backend_ack/unknown → verified_absent/present`。
- `delete_intent_durable` 必须在调用模组前完成耐久化屏障；重启后只读核验，
  不把 `absent` 或 `replaced` 自动解释为本次删除已确认成功。
- 任务展示历史默认保留 500 条；清理展示历史不得删除短信归档，也不得删除
  破坏性操作的幂等墓碑。墓碑无自动过期，容量达到上限时失败关闭并要求管理员
  把完整墓碑和任务查询索引迁移到容量充足的持久存储；不得靠删除或有损压缩幂等
  记录恢复设备删除能力。
- `batch_create` 只接受当前 128-bit 随机 `request_namespace`；旧命名空间的创建
  永远返回 `REQUEST_NAMESPACE_STALE`。同一认证主体仍可用旧命名空间执行
  `batch_lookup`/`batch_status` 查询既有任务；`batch_cancel` 仅在既有任务状态机
  仍允许取消时生效。
- 展示历史清理后仍须保留可按幂等唯一键精确查询的最小终态记录，包括
  `job_id`、服务端摘要、终态、未知计数和完成时间。达到墓碑上限但不能无损迁移时，
  破坏性任务保持失败关闭。

### FR-106 操作确认与进度

- 批量操作确认框显示操作类型、选择数量、来源分布和潜在物理分片数量。
- “移动”明确提示：归档成功后会删除设备原短信。
- “仅设备删除”和“设备与本地删除”必须要求二次确认。
- 提交后显示任务进度，可关闭窗口；重新进入页面后仍可恢复查看。
- RPC/HTTP 断线时显示“任务结果待确认”，使用提交前保存的 `request_id`
  找回 `job_id`，再继续轮询。
- 禁止把 transport timeout 统一映射为 `SERVICE_UNAVAILABLE`。
- 部分失败时允许“仅重试可安全重试项”；结果未知项默认不可重试。

### FR-107 本地搜索与筛选

- 支持在 `LOCAL` 中按时间、方向、来源、号码和正文关键词查询。
- 查询在本地执行，不触发 `SM/ME` 刷新。
- 搜索词不得写入系统日志、审计日志或 URL query string。
- 搜索结果仍适用 cursor、`snapshot_version` 与全选规则。

### FR-108 配置与容量

新增配置项的产品语义：

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `archive_enabled` | `0` | 新安装默认关闭；阶段 A 的存储、备份和恢复门禁通过后由部署流程显式启用 |
| `archive_path` | `/root/modem-sms/archive.sqlite3` | ZX7981PD 持久数据库路径 |
| `archive_max_messages` | `5000` | 最大归档条数 |
| `archive_max_bytes` | `8388608` | 数据库、索引、journal/WAL、任务与墓碑合计 8 MiB 上限 |
| `archive_min_free_bytes` | `12582912` | overlay 必须保留至少 12 MiB 可用空间 |
| `archive_store_raw_pdu` | `1` | root 专用保全；设为 0 时复制可用但移动和设备删除禁用 |
| `trash_retention_days` | `30` | 本地回收站保留天数 |
| `page_size_default` | `10` | 服务端默认分页大小 |
| `batch_chunk_items` | `1000` | 单个子任务上限 |
| `batch_selection_max` | `5000` | 一个不可变选择集合的硬上限 |
| `job_history_max` | `500` | 批量任务历史上限 |
| `idempotency_tombstone_max` | `5000` | 破坏性任务幂等墓碑上限，满额失败关闭 |
| `archive_sysupgrade_keep` | `1` | 默认把归档和任务状态纳入明确的 sysupgrade 保留清单 |

- 目标机实测 `/overlay` 总计约 46.5 MiB，审计时可用约 24.1 MiB；20 MiB
  归档上限不可接受。每次事务前必须估算主数据库及 journal/WAL/临时文件的峰值
  增长；只有“当前可用空间减去预计峰值增长”仍不少于
  `archive_min_free_bytes` 时才允许写入。
- 容量统计必须包含主数据库、索引、journal/WAL、临时事务、任务、pin 和幂等墓碑，
  不只统计正文表。一致性备份必须直接流式写入外部挂载或下载端，不得先在同一
  overlay 生成第二份完整数据库。
- 归档全部持久文件的实际总量不得超过 `archive_max_bytes`；达到条数、总字节上限
  或预计写后最低可用空间门槛中的任一项即停止新增归档。
- 低于安全余量时，在任何物理删除开始前失败关闭。
- 容量达到 80%/90% 时显示警告。
- 修改归档路径必须通过迁移工具，不能只改配置后静默使用空数据库。
- 默认路径中的 Mihomo 压缩核心和 OpenClash 备份是现有占用，不得由短信插件
  自动清理或覆盖。

### FR-109 模组存储唯一所有者

- 移动和所有设备删除的发布硬门禁是：系统中所有 `AT+CPMS`、
  `lteat.get_sms`、`lteat.del_sms` 和 `lteat.send_sms` 调用必须由
  一个持续运行的唯一传输代理独占或统一路由。
- 唯一传输代理必须实际拥有底层 TTY/QMI/厂商控制端点，通过设备节点权限、
  服务监督和 ubus ACL 阻止其他非 root 产品进程绕过；`modem-smsd` 只能通过该
  代理的版本化接口访问 SMS 存储。
- 代理向破坏性任务签发带随机 owner nonce 的独占 SMS 存储租约。租约覆盖
  “选择存储—读取—校验—删除—恢复存储”完整临界区，并在代理重启、transport
  重连、owner 进程退出、租约超时或检测到其他调用者时立即撤销。
- 启动、包升级和固件升级后必须重新审计目标文件系统、进程和 ubus 调用者；
  无法证明唯一所有者时，`exclusive_storage_owner:false`，UI 和 API 禁用移动
  及设备删除，只保留读取、分页和复制。
- 唯一所有权是持续能力，不是启动时的一次审计结果；每个物理删除前必须复核租约、
  owner nonce 和代理连续性。任一项变化立即返回 `STORAGE_LEASE_LOST`、更换扫描
  epoch，并停止所有尚未调用的物理删除。
- 守护进程内部的文件锁不能约束未知外部进程，不得作为唯一所有权或租约实现。
- 每个物理删除必须在同一串行操作中重新声明目标存储、重新读取目标位置、
  校验来源实例身份并调用删除。
- 后端若不能提供原子 `select-and-delete`，必须由唯一传输代理强制覆盖所有实际
  产品调用者；无法持续强制时阶段 C 永久保持禁用。

## 7. API 草案

保持现有 `modem.sms` API 向后兼容，新增以下方法：

| 方法 | 输入 | 关键输出 |
|---|---|---|
| `messages_page` | `box,source,query,cursor,limit,sort` | `items,next_cursor,prev_cursor,page_size,filtered_count,snapshot_version` |
| `selection_prepare` | `operation,scope,ids` 或当前筛选、排除项与 `snapshot_version` | `selection_token,count,source_counts,selection_digest,expires_at` |
| `batch_create` | `operation,selection_token,scope,request_namespace,request_id,confirm` | `job_id,state,count,selection_digest,request_digest` |
| `batch_status` | `job_id` | 阶段、计数、警告和安全错误码 |
| `batch_lookup` | `request_namespace,request_id` | `job_id,state,request_digest` |
| `batch_cancel` | `job_id` | `state,cancelled_pending` |
| `archive_get` | `archive_id` | 单条本地归档详情 |
| `archive_restore` | `archive_id` | 从本地回收站恢复 |
| `archive_purge` | `archive_id,confirm` | 永久删除结果 |

API 约束：

- 单条、当前页和全部筛选结果都必须先调用 `selection_prepare`；直接 ID 列表只可
  作为该方法的输入候选，服务端必须在同一线性化点解析为完整强身份并返回
  `selection_token`。`batch_create` 不接受裸 ID。
- `selection_token` 默认 10 分钟过期，只能用于原调用主体、操作、作用域和不可变
  成员集合，执行时禁止重新计算实时筛选。
- 选择集合不超过 1000 条时创建单个任务；1001–5000 条时创建一个父任务并按
  不超过 1000 条的不可变子集顺序执行。父任务总数必须等于确认总数，禁止静默
  截断。超过 5000 条时在确认前返回 `BATCH_TOO_LARGE`。
- 客户端显示并确认服务端返回的 `selection_digest`；`batch_create` 必须再次
  匹配该摘要。
- `request_digest` 由服务端使用规范序列化计算，必须覆盖认证主体、当前请求
  命名空间及影响结果的所有字段；客户端只保存并核对服务端返回值。
- `batch_create` 的 `confirm` 必须与操作匹配，例如
  `MOVE_AFTER_ARCHIVE`、`DELETE_DEVICE`、`DELETE_DEVICE_AND_LOCAL`。
- `batch_lookup` 是创建响应丢失后的唯一恢复入口；客户端不得因查不到 `job_id`
  自动生成新 `request_id` 重试。
- `query` 必须为有效 UTF-8，最长 256 字节；服务端使用参数绑定，单次查询执行
  上限 2 秒，超限返回 `QUERY_LIMIT_EXCEEDED`。
- `capabilities` 增加 API/schema 版本以及 archive、batch、cursor、backup、
  `exclusive_storage_owner` 能力，并返回当前 `request_namespace`。新旧前后端混用
  时按能力隐藏功能并安全降级。
- 产品级错误返回 `ok:false`；transport timeout 与产品错误分开呈现。
- 新增稳定错误码至少包括：
  - `ARCHIVE_DISABLED`
  - `ARCHIVE_FULL`
  - `ARCHIVE_IN_USE`
  - `ARCHIVE_NOT_LOSSLESS`
  - `ARCHIVE_WRITE_FAILED`
  - `ARCHIVE_VERIFY_FAILED`
  - `CURSOR_STALE`
  - `SELECTION_EXPIRED`
  - `SELECTION_CHANGED`
  - `SOURCE_CONTINUITY_LOST`
  - `BATCH_TOO_LARGE`
  - `JOB_NOT_FOUND`
  - `JOB_RESULT_UNKNOWN`
  - `REQUEST_ID_CONFLICT`
  - `REQUEST_NAMESPACE_STALE`
  - `QUERY_LIMIT_EXCEEDED`
  - `EXCLUSIVE_STORAGE_OWNER_UNVERIFIED`
  - `STORAGE_LEASE_LOST`
  - `STATE_STORE_UNAVAILABLE`
  - `RECOVERY_INCOMPLETE`
  - `UPGRADE_SNAPSHOT_FAILED`
  - `MOVE_PARTIAL`
  - `DELETE_PARTIAL`

## 8. 数据与一致性要求

### 8.1 建议数据实体

- `messages`：本地归档正文和规范化元数据。
- `message_sources`：历史与当前 `SM/ME` 物理位置、扫描 epoch、来源 generation、
  首次发现时间和原始 PDU SHA-256。
- `jobs`：批量父/子任务头、认证主体、请求命名空间、幂等请求 ID、服务端请求摘要
  和状态。
- `job_items`：逐条逻辑短信及逐物理分片的准备、意图、确认和核验状态。
- `selection_members`：token 对应的不可变成员集合、排除集合与摘要。
- `archive_pins`：移动任务对本地归档的持久引用。
- `idempotency_tombstones`：与展示历史分离的破坏性任务防重记录。
- `idempotency_namespaces`：当前/退役命名空间、轮换原因和不可回滚的创建拒绝边界。
- `trash`：本地软删除时间和计划清理时间。
- `metadata`：API/schema 版本、数据库版本、当前扫描 epoch、来源 generation
  计数器、破坏性操作高水位、最后迁移及备份/恢复状态。

### 8.2 事务边界

- 单条复制必须在一个本地事务内完成。
- 移动的本地事务提交必须先于任何物理删除。
- 任务状态必须在每个不可逆步骤前后持久化；每个物理分片在调用模组前必须提交
  `delete_intent_durable`。
- “持久化并校验”不是普通读回：必须完成存储引擎的 durable commit barrier，
  覆盖数据库、journal/WAL、任务状态、pin 和必要目录元数据。
- SQLite 技术设计必须明确 `synchronous`、journal 模式、checkpoint、fsync 和
  父目录持久化语义，并通过真实掉电/强制断电恢复测试；不满足时阶段 C 不得开放。
- 模组调用返回超时或进程在意图后中断时，保存
  `operation_outcome:unknown`；只读核验另存
  `current_presence:present|absent|replaced|unreadable`。`absent` 或
  `replaced` 不能自动升级为“本次删除成功”。
- 数据库升级使用版本化迁移；失败时保持旧版本可读或阻止服务启动并给出安全错误。
- 不允许因数据库损坏而回退到自动删除设备短信。
- 状态库不可写、durable barrier 失败、恢复未完成或无法保存幂等证据时，移动、
  “仅设备”和“设备和本地”删除全部失败关闭。

### 8.3 存储实现门槛

技术设计阶段优先评估 SQLite，但只有在目标固件依赖体积、可用绑定、原子提交、
文件锁和掉电恢复验证通过后才能采用。若改用其他格式，也必须满足：

- 原子写入；
- 崩溃恢复；
- 可分页索引；
- 条件搜索；
- 并发读与串行写；
- schema 迁移；
- 8 MiB 配置上限和 5000 条记录下的性能门槛；
- 可验证的 durable commit barrier 和外部一致性备份。

不得用单个无上限 JSON 文件实现正式归档。

目标机审计时未安装 SQLite CLI 或 ucode SQLite 绑定。阶段 A 开始编码前必须完成
依赖体积、绑定可用性、交叉编译、锁语义和 UBIFS 掉电恢复技术验证；验证失败则
回到满足同等门槛的替代存储设计，不得以 shell 拼接 SQL 作为正式后端。

## 9. 权限、隐私与审计

- 仅 LuCI 管理员和 root CLI 可读取完整归档。
- RPC ACL 明确分为：元数据读取、正文读取、归档写入、设备删除、永久清理；
  `send` 与设备删除不得因历史 ACL 设计继续共用同一不可区分权限。
- `messages_page` 默认返回脱敏号码和正文摘要；完整正文仅由正文读取权限通过
  `archive_get` 获取。
- 数据库可保存完整号码和正文，但必须为 `0600`，不得通过普通日志输出。
- 原始 PDU 只能由存储后端、迁移和 root 一致性备份/恢复流程访问；LuCI RPC 不提供
  原始 PDU 读取方法。
- 不声称静态加密，除非实际实现并验证密钥管理；设备文件权限是首版最低保护。
- 审计记录时间、任务 ID、操作类型、数量、脱敏来源和结果码，不记录正文。
- 云同步、通用导出和远程转发不在本 PRD 范围；但安装、升级、降级、迁移和恢复
  所需的一致性备份、SHA-256 校验、隐私提示和恢复命令属于强制范围。
- 提供 root CLI 一致性备份/恢复命令，备份只能直接写往显式外部挂载路径或通过
  经授权下载流输出，不得在 overlay 留下第二份临时正文数据库。
- 备份清单必须包含数据库 schema、归档内容摘要、破坏性操作高水位、当前及退役
  请求命名空间和备份生成时间；恢复前必须停写并校验完整性。
- 恢复采用前向合并，不得用较旧备份静默覆盖当前数据库、删除较新的归档、pin、
  删除意图或墓碑。若当前库不可读，恢复工具必须保留原文件，载入备份后设置
  `recovery_incomplete:true`，把恢复出的非终态破坏性任务标记为不可执行
  `unknown`，并禁用全部设备删除直至管理员完成审计式核销。
- 每次恢复都必须先耐久轮换 128-bit 随机 `request_namespace`；旧命名空间永久
  拒绝 `batch_create`，但保留原主体对既有任务的只读查询，避免旧 `request_id`
  在回滚后重新执行且不破坏响应丢失恢复。恢复不得自动续跑备份中的移动或设备
  删除任务。
- `/lib/upgrade/keep.d/modem-sms` 必须明确列出 `/root/modem-sms` 中需要保留的
  数据库、任务、pin 和幂等墓碑；默认 `archive_sysupgrade_keep=1`。
- `keep.d` 只负责文件纳入范围，不构成一致性保证。sysupgrade 打包前钩子必须：
  1. 获取全局维护锁并停止接收新任务；
  2. 等待进行中的写操作到达已定义安全点，结果未知项保持 pin；
  3. 静默所有数据库写入并停止相关守护进程；
  4. 完成 journal/WAL checkpoint、durable barrier 和目录 fsync；
  5. 对即将打包的只读快照执行完整性检查和清单 SHA-256 校验。
  任一步失败必须返回 `UPGRADE_SNAPSHOT_FAILED` 并中止升级，不得复制运行中的
  数据库继续 sysupgrade。
- 新固件首次启动必须先校验数据库、任务、pin、墓碑和命名空间一致性，再恢复服务；
  校验失败时保持 `recovery_incomplete:true` 并禁用全部设备删除。
- sysupgrade 备份会包含完整号码和正文，UI、CLI 与部署文档必须在创建备份前
  明确提示其敏感性；用户显式关闭保留时，移动和设备删除保持禁用，直到存在经
  校验的外部备份策略。
- 包升级、降级和卸载不得删除 `/root/modem-sms`。永久清理必须使用单独确认命令。

## 10. 性能与可靠性

- 本地第一页 10 条 P95 ≤ 500 ms。
- 5000 条本地记录下，任意允许分页大小 P95 ≤ 1 秒。
- `batch_create` P95 ≤ 1 秒。
- UI 中不允许存在等待 10 秒以上才返回的写 RPC；硬件操作必须后台化。
- 复制/移动/删除期间 `usb0` 不 down、不重新获取地址。
- 页面关闭、浏览器刷新和 LuCI session 过期不影响已接受任务。
- 模组存储不可用时，本地归档分页仍可用。
- 数据库不可写、无法耐久提交或恢复未完成时，复制、移动和所有设备删除均失败
  关闭；“仅设备删除”也不得绕过任务状态、安全副本、pin 和幂等门禁。
- P95 验收使用固定 5000 条数据集，每种分页大小至少 100 次独立请求，分别记录
  冷启动首请求和数据库已打开的温请求；报告目标机固件、可用空间、并发任务数、
  测量命令和原始样本。
- `batch_create` P95 使用至少 100 次不触发模组写入的任务创建样本；不得把后台
  执行时间混入创建响应指标。

## 11. 异常处理矩阵

| 场景 | 预期行为 |
|---|---|
| 本地落盘或任务状态持久化失败 | 复制、移动和所有设备删除失败关闭，设备零删除 |
| 初始破坏性校验发现成员身份变化 | 整个任务 `SELECTION_CHANGED`，零写操作 |
| 复制任务发现成员身份变化 | 该项 `MESSAGE_CHANGED`，其他安全复制项可继续 |
| 破坏性任务开始后发现成员身份变化 | 停止所有尚未调用的设备删除，任务 `partial` |
| 解码失败/不完整/关联歧义 | 允许不完整复制；禁止移动和逻辑级设备删除 |
| 单个存储读取失败 | 涉及设备删除的项目不执行删除 |
| 多分片部分删除 | 任务 `partial`，记录已确认删除数量，不自动重试未知项 |
| 删除 RPC/后端超时 | `operation_outcome=unknown`；只读记录当前存在性，UI 不显示明确失败 |
| 默认存储恢复失败 | 返回警告并阻止后续模组任务，直至恢复或人工处置 |
| 创建响应丢失/浏览器断线 | 任务继续，按原主体、命名空间和预存 `request_id` 找回 `job_id` |
| 守护进程重启 | 恢复任务；不可逆步骤结果未知时不自动重复 |
| 模组重置或来源连续性丢失 | 更换扫描 epoch；旧选择失效，待删除项目返回 `SOURCE_CONTINUITY_LOST` |
| 本地数据库损坏 | `LOCAL` 只读或不可用；禁止所有设备删除，不影响 `usb0` |
| cursor 过期 | 页面重新加载；已物化选择不因无关新增失效 |
| selection token 过期或成员身份变化 | 要求重新选择，零写操作 |
| token 创建后有新短信到达 | 既有不可变成员集合不变，新短信不进入任务 |
| 活动设备删除的安全副本被清理 | 返回 `ARCHIVE_IN_USE`，零删除 |
| 备份恢复 | 停写并轮换请求命名空间；旧创建被拒绝、既有任务可查询且不续跑 |
| 幂等墓碑满额 | 破坏性任务失败关闭；只允许无损迁移完整查询索引，不允许删除压缩 |
| 无法证明 CPMS 唯一所有者或租约丢失 | 禁用移动和设备删除；停止尚未调用的物理删除 |
| overlay 低于 12 MiB 安全余量 | 禁止新增归档和任何依赖归档的物理删除 |
| sysupgrade 保留关闭且无外部备份 | 禁用移动和设备删除 |

## 12. 验收标准

1. 默认每页显示 10 条，可选择 10、20、50、100，刷新页面后保持设置。
2. 当前页全选只选择当前页；“全部筛选结果”原子物化不可变成员集合。token 创建后
   新到达的匹配短信不得进入任务，取消选择项不得被执行。
3. 翻页、筛选和排序期间不出现重复行或漏行；数据变化时安全返回 `CURSOR_STALE`。
4. 复制 1 条和批量复制 100 条后，设备原短信仍存在，本地只生成一份归档。
5. 1001–5000 条选择通过父/子任务完整处理；终态时成功、失败、跳过、未知和取消
   之和必须等于确认数。超过 5000 条在确认前拒绝，任何场景不得静默截断。
6. 相同认证主体、请求命名空间、`request_id` 和服务端 `request_digest` 不得重复
   归档或重复删除；同一幂等键不同摘要返回 `REQUEST_ID_CONFLICT`。创建响应丢失后
   能按原主体、命名空间和 `request_id` 找回原任务，跨主体访问被拒绝。
7. 移动前验证原始 PDU 已逐字节持久化、`lossless_archivable:true`、完整 PDU
   SHA-256、扫描 epoch、来源 generation、物理位置、归档 pin 与 durable commit
   barrier；任一失败时 `SM/ME` 零删除。
8. 解码失败、不完整、关联歧义和来源读取不完整的短信只能复制为不完整归档，
   移动和逻辑级设备删除被拒绝。
9. 成功移动后短信仍可在 `LOCAL` 查看，设备容量相应释放；真实强制断电恢复后
   本地记录、任务状态和 pin 保持一致。
10. 多分片短信作为一条选择并处理；部分失败显示每个物理位置的意图、确认、未知
    和当前存在性，结果未知不得自动重试。
11. 批量删除可明确选择仅设备、仅本地、设备和本地；所有设备作用域都先具有已
    校验的无损安全副本和耐久 pin，且无默认高风险作用域。
12. 本地删除进入回收站，可在保留期内恢复；被任何设备删除任务 pin 的记录永久
    清理返回 `ARCHIVE_IN_USE`，结果 `unknown` 时 pin 不自动释放。
13. 所有设备写操作立即返回 `job_id`；超过 30 秒的任务不显示
    `SERVICE_UNAVAILABLE` 假失败。
14. 浏览器关闭后任务继续；守护进程重启或来源连续性丢失后不重复不可逆操作，
    旧选择失败关闭，展示历史清理不移除破坏性幂等墓碑；备份恢复轮换请求命名
    空间，旧命名空间拒绝新建但仍可由原主体查询既有任务。
15. 5000 条记录分页性能按第 10 节固定样本方法达到门槛。
16. overlay 始终保留至少 12 MiB 安全余量；数据库及附属文件总量不超过 8 MiB。
17. 普通日志、审计和任务状态不包含短信正文、完整号码或完整 PDU。
18. 五类 ACL 越权调用均被拒绝；新旧前后端组合按 `capabilities` 安全降级。
19. 安装、升级、降级、回滚、卸载和 sysupgrade 有设备实测；sysupgrade 打包前
    完成停写、checkpoint、durable barrier 与快照校验，失败时中止升级；一致性
    备份可校验、可恢复，归档不被静默泄露或丢失。
20. 无法持续强制全局 CPMS 唯一所有者或执行中租约丢失时，移动和设备删除入口在
    UI/API/CLI 均不可用，尚未调用的物理删除全部停止。
21. 全流程不改变 `usb0` 地址、默认路由或现有 5G 数据业务。

## 13. 测试要求

- 本地数据库 schema、迁移、容量和损坏恢复单元测试。
- cursor、筛选、排序和不可变 `selection_token` 的边界测试；token 创建后插入新
  匹配短信、排除单项、单条/当前页直接 ID 物化和 1000/1001/5000/5001 条均需
  覆盖；无关新增不得使已物化集合失效，成员替换必须失效。

- 原始 PDU SHA-256、扫描 epoch、来源 generation、索引复用和同号码/同正文/

- 原始 PDU 逐字节保存/读回/哈希校验、RPC 不可读取，以及关闭 PDU 保全后移动能力
  自动禁用测试。
- 模拟归档写失败、journal/WAL 故障、掉电、进程重启和任务恢复。
- 在专用测试环境执行数据库提交后、删除意图后、模组返回前和返回后强制断电测试。

- 模拟多分片部分删除与删除结果未知。
- 模拟其他进程切换 CPMS、传输代理重启、owner nonce 变化和执行中租约丢失；

  测试；覆盖数据库写入中触发 sysupgrade、checkpoint/fsync/校验失败时中止升级，
  恢复后必须轮换请求命名空间，非终态破坏性任务不得续跑。
- 前端多标签页、页面刷新和 session 过期恢复测试。
- 真实 ZX7981PD 上执行只读、复制、单条移动和小批量移动验收。
- 真实删除测试必须使用用户明确指定的测试短信，不得使用历史私人短信。
- 测试前后记录 `usb0` 地址、路由、服务状态和存储容量。

## 14. 发布与回滚

建议分三阶段发布：

1. **阶段 A：存储基础、单条复制与分页**

   完成存储引擎验证、持久路径、schema 迁移、单条复制、分页、搜索、容量门禁、
   一致性备份/恢复和 sysupgrade 保留，不执行设备删除。
2. **阶段 B：复制与异步任务**

   开放不可变全选、批量复制、父/子任务、任务进度、按 `request_id` 恢复、pin、
   幂等墓碑和审计，仍不执行设备删除。
3. **阶段 C：移动与批量删除**

   仅在无损归档、强来源身份、durable commit barrier、真实掉电恢复、持续强制的
   全局 CPMS 唯一传输代理与租约、空间安全余量、前向合并恢复和真机故障注入全部
   通过后，开放两阶段移动和设备删除。任一能力回退时立即隐藏并拒绝这些入口。

回滚要求：

- 回滚应用包不得删除 `LOCAL` 数据。
- 旧版本无法理解新数据库时必须停止归档写入并提示版本不兼容。
- 永久清理数据库必须由管理员单独确认，不得由卸载脚本默认执行。
- 包卸载保留 `/root/modem-sms`；用户数据不作为普通 conffile 合并。
- sysupgrade 使用明确的 `keep.d` 清单和升级前一致性冻结/校验钩子；关闭保留且
  没有经校验外部备份时，移动和设备删除保持禁用。
- 发布包必须提供一致性数据库备份、SHA-256 校验和恢复工具及实测说明。

## 15. 待技术设计确认

以下项目的产品语义已经确定，但实现方案必须在对应阶段编码前通过技术设计评审：

1. `/root/modem-sms` 在目标固件 overlay、sysupgrade、降级和卸载中的实际行为。
2. SQLite/替代存储方案、OpenWrt 包依赖增量、UBIFS 锁和 durable commit barrier。
3. 8 MiB 总预算、12 MiB 安全余量、journal/WAL 和外部流式备份的空间模型。
4. 任务逐分片状态、所有设备删除的 pin、请求命名空间、幂等墓碑和 daemon 重启
   恢复机制。
5. 原始 PDU SHA-256、扫描 epoch、source generation 和失去连续观察后的失败关闭。
6. 不可变 `selection_token`、排除项、父/子任务和集合摘要实现。
7. 五类方法级 ACL 与 API/schema 版本协商。
8. 全局 CPMS 唯一传输代理、持续访问控制、owner nonce、独占租约和升级后复核
   机制。
9. 本地回收站自动清理、活动 pin 跳过，以及墓碑满额后的完整查询索引迁移机制。

## 16. 对抗性审计修订记录

0.2 版根据独立只读对抗性审计完成以下收口：

1. 增加原始 PDU 逐字节保全与无损归档门槛，禁止移动解码失败、不完整或关联不可信
   短信。
2. 设备删除改用原始 PDU SHA-256、扫描 epoch、来源 generation、物理位置和算法
   版本共同校验。
3. 明确删除前 durable commit barrier、逐分片删除意图和掉电恢复状态。
4. 增加按 `request_id` 找回任务、规范请求摘要和永久幂等墓碑。
5. 全选改为不可变物化集合，并明确 1000 条分片与 5000 条硬上限。
6. 增加移动归档 pin，阻止并发永久清理。
7. 把系统级 CPMS 唯一所有者设为阶段 C 硬门禁。
8. 确定 ZX 默认持久路径、8 MiB 预算、12 MiB 安全余量、sysupgrade 保留及
   外部一致性备份/恢复范围。
9. 第二轮闭环复核进一步禁止状态库不可写时的任何设备删除，并把设备删除统一绑定
   到已校验无损安全副本与耐久 pin。
10. 增加认证主体绑定、服务端请求摘要、不可回滚请求命名空间轮换和旧备份前向合并
    恢复规则。
11. 消除快照新增与不可变选择的冲突，移除 `batch_create` 裸 ID 路径并补齐全部
    终态计数。
12. 把 CPMS 所有权从时点审计升级为唯一传输代理持续强制和逐次删除租约复核。
