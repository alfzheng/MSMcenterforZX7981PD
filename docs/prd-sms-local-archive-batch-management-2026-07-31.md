# 短信中心本地归档、批量管理与分页 PRD

版本：0.1（评审稿）

日期：2026-07-31

关联产品：ZX7981PD LuCI 短信中心

关联主 PRD：`PRD.md` 1.3

目标发布：待技术设计、目标机存储评估和评审通过后确定

## 1. 背景

当前短信中心能够读取 `SM`（SIM 卡）与 `ME`（移动设备/模组）中的短信，但列表快照
只保存在守护进程内存中。守护进程重启后必须重新扫描模组，短信从 `SM/ME` 删除后也
没有插件侧副本。

ZX7981PD 现场完整读取 `SM/ME` 约需 23–44 秒。单条删除为了防止存储索引复用导致
误删，会先重新读取双存储，再执行物理删除并恢复默认存储。该同步操作可能超过 LuCI
RPC 的等待时间：目标机已经观察到后端记录 `delete_complete state=deleted`，但前端
仍显示 `SERVICE_UNAVAILABLE` 的假失败。

用户需要：

1. 将短信复制或安全移动到插件自己的持久存储。
2. 多选、选择当前页和选择全部筛选结果。
3. 批量复制、移动和删除。
4. 分页显示，并可选择每页数量，默认 10 条。
5. 长操作有可查询的真实状态，不再用 `SERVICE_UNAVAILABLE` 表示未知结果。

## 2. 名词与产品边界

| 名词 | 定义 |
|---|---|
| `SM` | SIM 卡短信存储 |
| `ME` | 5G 模组/移动设备短信存储 |
| `LOCAL` | 本插件管理的本地持久短信归档 |
| 短信中心 | 本产品及其 `LOCAL` 归档，不是运营商 SMSC 号码或网络侧短信中心 |
| 逻辑短信 | UI 中的一条短信；可能对应一个或多个物理 PDU 分片 |
| 物理位置 | `SM/ME` 中具体的存储区与索引 |
| 复制 | 持久写入 `LOCAL`，保留 `SM/ME` 原记录 |
| 移动 | 先持久写入并校验 `LOCAL`，再删除 `SM/ME` 原记录 |
| 批量任务 | 后台执行、可查询状态、可恢复和可审计的复制/移动/删除操作 |

本 PRD 不改变运营商 SMSC 配置，不增加任意 AT 命令入口，也不允许浏览器直接访问
`lteat`。

## 3. 产品目标

### 3.1 目标

- 页面优先从 `LOCAL` 与现有内存快照生成列表，不因模组冷扫描阻塞首屏。
- 管理员可以安全批量复制、移动和删除逻辑短信。
- 所有可能超过 RPC 等待时间的写操作都转为后台任务。
- 移动必须满足“本地归档已持久化并校验成功”后才允许删除物理记录。
- 分页、筛选和排序在大量本地短信下仍保持稳定、可重复。
- 超时、重启、分片部分失败和客户端断线不得造成静默重复删除。

### 3.2 非目标

- 不自动把所有新短信从 `SM/ME` 删除。
- 不提供无确认的“一键清空全部存储”。
- 不把 `LOCAL` 当作运营商投递成功凭证。
- 不在本阶段提供云同步、邮件转发、Webhook 或多设备共享。
- 不承诺插件停机期间突破 `SM/ME` 的物理容量限制。
- 不在日志、任务摘要或诊断包中记录短信正文、完整号码或完整 PDU。

## 4. 用户故事

### US-01 本地保留

管理员选择一条或多条 `SM/ME` 短信，点击“复制到短信中心”，归档成功后仍可在
原存储看到短信。

### US-02 安全释放模组容量

管理员选择短信并点击“移动到短信中心”。系统先归档、落盘和校验，再删除全部关联的
物理分片。归档失败时不得触碰 `SM/ME`。

### US-03 批量清理

管理员按收件箱、发件箱、来源、日期或关键词筛选，选择当前页或全部筛选结果，提交
批量删除任务，并看到逐项进度与部分失败原因。

### US-04 大量历史浏览

管理员浏览本地归档，默认每页 10 条，可以切换 20、50 或 100 条，并在翻页后保持
筛选、排序和每页数量设置。

### US-05 超时后确认真实结果

浏览器断线或 RPC 超时后，管理员通过任务 ID 继续查询状态。系统不得把结果未知显示为
明确失败，也不得自动重复移动或删除。

## 5. 信息架构

### 5.1 统一列表

列表支持以下维度：

- 信箱：收件箱、发件箱、全部。
- 来源：全部、`SM`、`ME`、`LOCAL`。
- 状态：设备中、本地已归档、设备与本地均存在、仅本地、处理中、部分失败。
- 时间范围：全部、自定义起止日期。
- 号码/关键词：仅在管理员显式搜索时查询，不写入日志。
- 排序：时间降序（默认）、时间升序、首次归档时间。

列表行必须显示：

- 选择框；
- 时间；
- 脱敏号码；
- 正文摘要；
- 方向与状态；
- 来源标签（`SM`、`ME`、`LOCAL`，可多选）；
- 分片完整度；
- 当前批量任务状态；
- 单条详情与单条操作入口。

### 5.2 分页

- 默认每页 10 条。
- 可选 10、20、50、100 条。
- 每页数量保存在浏览器本地设置中；非法或过期值回退到 10。
- 后端使用稳定 cursor 分页，不使用仅依赖可变数组下标的分页。
- 默认排序键为 `timestamp DESC, archive_id DESC`；无时间短信使用
  `first_seen_at DESC, archive_id DESC`。
- 响应返回 `items`、`next_cursor`、`prev_cursor`、`page_size`、
  `filtered_count` 和 `snapshot_version`。
- 数据变化导致 cursor 失效时返回 `CURSOR_STALE`，前端回到第一页并保留筛选条件。

### 5.3 选择模型

- 行复选框选择单条逻辑短信。
- 表头复选框只选择或取消当前页。
- 当前页全选后显示“已选择本页 N 条；选择全部 M 条筛选结果”。
- “选择全部筛选结果”必须生成带过期时间和 `snapshot_version` 的服务端
  `selection_token`，不能把无限 ID 列表放进浏览器或 RPC 请求。
- 改变筛选条件后，旧 `selection_token` 立即失效。
- 操作栏显示总选择数以及 `SM/ME/LOCAL` 分布。
- 长短信按一条逻辑短信选择；禁止只选择其中一个已安全拼接的物理分片。

## 6. 功能需求

### FR-101 本地持久归档

- `LOCAL` 必须在设备重启和守护进程重启后保留。
- 归档记录至少包含：
  - `archive_id`；
  - 当前逻辑消息指纹；
  - 方向、号码、正文、时间、编码与分片完整度；
  - 原始来源、原始物理位置和首次/最近发现时间；
  - 归档时间、更新时间和删除状态；
  - 当前是否仍存在于 `SM/ME`。
- 不保存完整原始 PDU，除非后续安全评审单独批准。
- 对同一 `message_id + fingerprint` 重复复制必须幂等返回既有 `archive_id`。
- 同一索引被模组复用且指纹变化时必须创建新归档记录，不能覆盖历史短信。
- 不跨 `SM/ME` 仅按正文自动合并，以保持现有防误删边界。
- 数据文件权限为 `0600`，目录仅 root 可访问。
- 持久路径必须可配置；不得默认使用重启即清空的 `/tmp` 或 `/var`。
- 发布前必须在目标机确认 overlay 可用空间、写放大和 sysupgrade 行为。
- 本地归档达到容量上限时停止新增并返回 `ARCHIVE_FULL`；默认不自动删除旧短信。

### FR-102 复制到短信中心

- 复制仅适用于当前仍存在于 `SM/ME` 的逻辑短信。
- 任务执行时重新确认消息指纹；不匹配返回 `MESSAGE_CHANGED`。
- 本地写入必须经过事务提交、落盘和读回校验后才返回成功。
- 已归档记录返回 `already_archived:true`，不创建重复正文。
- 复制不得删除或修改任何 `SM/ME` 物理位置。

### FR-103 移动到短信中心

- 移动采用两阶段流程：
  1. 归档阶段：写入 `LOCAL`、持久化并校验；
  2. 删除阶段：重新读取相关存储、验证指纹并逐个删除物理分片。
- 归档阶段失败时，删除阶段绝不能开始。
- 删除阶段失败时保留本地归档，并将任务标记为 `partial`、`unknown` 或 `failed`；
  不自动重试结果未知的删除。
- 多分片短信只有在所有分片归档完成后才可开始物理删除。
- 移动完成后列表记录保留，来源更新为 `LOCAL`，并显示原来源。
- 默认存储恢复失败但物理删除已完成时，任务返回
  `completed_with_warning`，不得显示为“未删除”。

### FR-104 删除

删除必须明确作用域：

| 作用域 | 行为 |
|---|---|
| 仅设备 | 删除 `SM/ME` 物理记录，保留 `LOCAL` |
| 仅本地 | 移入本地回收站，不触碰 `SM/ME` |
| 设备和本地 | 先删除设备记录，确认结果后再将本地记录移入回收站 |

- 对同时存在于设备和本地的记录，确认框不得预选“设备和本地”。
- 删除设备短信前必须重新读取目标存储并验证消息指纹。
- 多分片短信逐分片记录结果；部分删除必须返回成功数、失败位置和结果未知位置。
- 本地删除默认进入回收站，保留 30 天；永久删除需要再次确认。
- 回收站保留天数可配置为 1–365 天；设为 0 表示禁用自动清理，不表示立即删除。
- 任何超时都不得自动重复删除。

### FR-105 异步批量任务

复制、移动和设备删除必须通过后台任务执行。

任务状态：

`accepted → validating → archiving → deleting → verifying → completed`

异常终态：

- `completed_with_warning`
- `partial`
- `failed`
- `unknown`
- `cancelled`

要求：

- 创建任务必须在 1 秒内返回 `job_id`，不等待模组操作完成。
- 每个任务带调用方生成的 `request_id`；重复提交返回原任务。
- 状态包含总数、已处理、成功、跳过、失败、未知和当前阶段。
- 状态必须提供安全错误码，不返回短信正文或完整号码。
- 任务开始物理删除前允许取消；进入删除阶段后只能停止尚未开始的项目。
- 守护进程重启后恢复任务元数据。对结果未知的物理删除不得自动重做。
- 同一时间最多执行一个访问模组的 SMS 操作；纯本地分页和读取不应被阻塞。
- 任务历史默认保留 500 条；清理历史不得删除短信归档。

### FR-106 操作确认与进度

- 批量操作确认框显示操作类型、选择数量、来源分布和潜在物理分片数量。
- “移动”明确提示：归档成功后会删除设备原短信。
- “仅设备删除”和“设备与本地删除”必须要求二次确认。
- 提交后显示任务进度，可关闭窗口；重新进入页面后仍可恢复查看。
- RPC/HTTP 断线时显示“任务结果待确认”，保留 `job_id` 并继续轮询。
- 禁止把 transport timeout 统一映射为 `SERVICE_UNAVAILABLE`。
- 部分失败时允许“仅重试可安全重试项”；结果未知项默认不可重试。

### FR-107 本地搜索与筛选

- 支持在 `LOCAL` 中按时间、方向、来源、号码和正文关键词查询。
- 查询在本地执行，不触发 `SM/ME` 刷新。
- 搜索词不得写入系统日志、审计日志或 URL query string。
- 搜索结果仍适用 cursor、`snapshot_version` 与全选规则。

### FR-108 配置与容量

新增配置项的产品语义：

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `archive_enabled` | `1` | 启用本地归档 |
| `archive_path` | 发布前目标机评估确定 | 持久数据库路径 |
| `archive_max_messages` | `5000` | 最大归档条数 |
| `archive_max_bytes` | `20971520` | 20 MiB 软上限 |
| `trash_retention_days` | `30` | 本地回收站保留天数 |
| `page_size_default` | `10` | 服务端默认分页大小 |
| `batch_max_items` | `1000` | 单个批量任务上限 |
| `job_history_max` | `500` | 批量任务历史上限 |

- 同时达到条数或字节上限即停止新增归档。
- 容量达到 80%/90% 时显示警告。
- 修改归档路径必须通过迁移工具，不能只改配置后静默使用空数据库。

## 7. API 草案

保持现有 `modem.sms` API 向后兼容，新增以下方法：

| 方法 | 输入 | 关键输出 |
|---|---|---|
| `messages_page` | `box,source,query,cursor,limit,sort` | `items,next_cursor,filtered_count,snapshot_version` |
| `selection_prepare` | 当前筛选与 `snapshot_version` | `selection_token,count,expires_at` |
| `batch_create` | `operation,ids/selection_token,scope,request_id,confirm` | `job_id,state` |
| `batch_status` | `job_id` | 阶段、计数、警告和安全错误码 |
| `batch_cancel` | `job_id` | `state,cancelled_pending` |
| `archive_get` | `archive_id` | 单条本地归档详情 |
| `archive_restore` | `archive_id` | 从本地回收站恢复 |
| `archive_purge` | `archive_id,confirm` | 永久删除结果 |

API 约束：

- `ids` 最多 100 条；超过 100 条必须使用 `selection_token`。
- `selection_token` 默认 10 分钟过期，只能用于原筛选与快照。
- `batch_create` 的 `confirm` 必须与操作匹配，例如
  `MOVE_AFTER_ARCHIVE`、`DELETE_DEVICE`、`DELETE_DEVICE_AND_LOCAL`。
- 产品级错误返回 `ok:false`；transport timeout 与产品错误分开呈现。
- 新增稳定错误码至少包括：
  - `ARCHIVE_DISABLED`
  - `ARCHIVE_FULL`
  - `ARCHIVE_WRITE_FAILED`
  - `ARCHIVE_VERIFY_FAILED`
  - `CURSOR_STALE`
  - `SELECTION_EXPIRED`
  - `BATCH_TOO_LARGE`
  - `JOB_NOT_FOUND`
  - `JOB_RESULT_UNKNOWN`
  - `MOVE_PARTIAL`
  - `DELETE_PARTIAL`

## 8. 数据与一致性要求

### 8.1 建议数据实体

- `messages`：本地归档正文和规范化元数据。
- `message_sources`：历史与当前 `SM/ME` 物理位置。
- `jobs`：批量任务头、幂等请求 ID 和状态。
- `job_items`：逐条逻辑短信的阶段与结果。
- `trash`：本地软删除时间和计划清理时间。
- `metadata`：schema 版本、数据库版本和最后迁移状态。

### 8.2 事务边界

- 单条复制必须在一个本地事务内完成。
- 移动的本地事务提交必须先于任何物理删除。
- 任务状态必须在每个不可逆步骤前后持久化。
- 数据库升级使用版本化迁移；失败时保持旧版本可读或阻止服务启动并给出安全错误。
- 不允许因数据库损坏而回退到自动删除设备短信。

### 8.3 存储实现门槛

技术设计阶段优先评估 SQLite，但只有在目标固件依赖体积、可用绑定、原子提交、
文件锁和掉电恢复验证通过后才能采用。若改用其他格式，也必须满足：

- 原子写入；
- 崩溃恢复；
- 可分页索引；
- 条件搜索；
- 并发读与串行写；
- schema 迁移；
- 20 MiB 数据规模下的性能门槛。

不得用单个无上限 JSON 文件实现正式归档。

## 9. 权限、隐私与审计

- 仅 LuCI 管理员和 root CLI 可读取完整归档。
- RPC ACL 分离只读分页、归档写入和设备删除权限。
- 数据库可保存完整号码和正文，但必须为 `0600`，不得通过普通日志输出。
- 不声称静态加密，除非实际实现并验证密钥管理；设备文件权限是首版最低保护。
- 审计记录时间、任务 ID、操作类型、数量、脱敏来源和结果码，不记录正文。
- 导出、备份和远程同步不在本 PRD 范围，后续必须单独授权。
- sysupgrade 是否包含归档数据库必须明确配置并在 UI 提示，不能隐式泄露或隐式丢失。

## 10. 性能与可靠性

- 本地第一页 10 条 P95 ≤ 500 ms。
- 5000 条本地记录下，任意允许分页大小 P95 ≤ 1 秒。
- `batch_create` P95 ≤ 1 秒。
- UI 中不允许存在等待 10 秒以上才返回的写 RPC；硬件操作必须后台化。
- 复制/移动/删除期间 `usb0` 不 down、不重新获取地址。
- 页面关闭、浏览器刷新和 LuCI session 过期不影响已接受任务。
- 模组存储不可用时，本地归档分页仍可用。
- 数据库不可写时，复制和移动失败关闭；仅设备删除必须单独确认，不得伪装成移动。

## 11. 异常处理矩阵

| 场景 | 预期行为 |
|---|---|
| 本地落盘失败 | 复制/移动失败，不删除设备短信 |
| 指纹变化 | 该项 `MESSAGE_CHANGED`，其他安全项可继续 |
| 单个存储读取失败 | 涉及设备删除的项目不执行删除 |
| 多分片部分删除 | 任务 `partial`，记录已确认删除数量，不自动重试未知项 |
| 删除 RPC/后端超时 | 任务 `unknown`，后台核验；UI 不显示明确失败 |
| 默认存储恢复失败 | 返回警告并阻止后续模组任务，直至恢复或人工处置 |
| 浏览器断线 | 任务继续，重新登录后按 `job_id` 查询 |
| 守护进程重启 | 恢复任务；不可逆步骤结果未知时不自动重复 |
| 本地数据库损坏 | `LOCAL` 只读或不可用；禁止移动，不影响 `usb0` |
| cursor/选择快照过期 | 要求重新加载和重新选择，不使用旧选择执行写操作 |

## 12. 验收标准

1. 默认每页显示 10 条，可选择 10、20、50、100，刷新页面后保持设置。
2. 当前页全选只选择当前页；“全部筛选结果”显示准确总数并使用服务端 token。
3. 翻页、筛选和排序期间不出现重复行或漏行；数据变化时安全返回 `CURSOR_STALE`。
4. 复制 1 条和批量复制 100 条后，设备原短信仍存在，本地只生成一份归档。
5. 重复提交相同 `request_id` 不得重复归档或重复删除。
6. 移动时先验证本地持久记录；人为制造归档失败后，`SM/ME` 零删除。
7. 成功移动后短信仍可在 `LOCAL` 查看，设备容量相应释放。
8. 多分片短信作为一条选择并处理；部分失败显示精确数量和安全错误码。
9. 批量删除可明确选择仅设备、仅本地、设备和本地；无默认高风险作用域。
10. 本地删除进入回收站，可在保留期内恢复；永久删除需要再次确认。
11. 所有设备写操作立即返回 `job_id`；超过 30 秒的任务不显示
    `SERVICE_UNAVAILABLE` 假失败。
12. 浏览器关闭后任务继续；重启守护进程后不重复不可逆操作。
13. 5000 条记录分页性能达到第 10 节门槛。
14. 普通日志、审计和任务状态不包含短信正文、完整号码或完整 PDU。
15. ACL 越权调用复制、移动、设备删除和永久清理均被拒绝。
16. 安装、升级、回滚和 sysupgrade 行为有设备实测记录；归档不被静默丢失。
17. 全流程不改变 `usb0` 地址、默认路由或现有 5G 数据业务。

## 13. 测试要求

- 本地数据库 schema、迁移、容量和损坏恢复单元测试。
- cursor、筛选、排序和 `selection_token` 的边界测试。
- 复制/移动/删除幂等测试。
- 模拟归档写失败、掉电、进程重启和任务恢复。
- 模拟多分片部分删除与删除结果未知。
- 前端多标签页、页面刷新和 session 过期恢复测试。
- 真实 ZX7981PD 上执行只读、复制、单条移动和小批量移动验收。
- 真实删除测试必须使用用户明确指定的测试短信，不得使用历史私人短信。
- 测试前后记录 `usb0` 地址、路由、服务状态和存储容量。

## 14. 发布与回滚

建议分三阶段发布：

1. **阶段 A：本地归档只读与分页**

   引入持久数据库、迁移、分页和搜索，不执行设备删除。
2. **阶段 B：复制与异步任务**

   开放批量复制、任务进度、恢复和审计。
3. **阶段 C：移动与批量删除**

   完成真机故障注入后开放两阶段移动和设备删除。

回滚要求：

- 回滚应用包不得删除 `LOCAL` 数据。
- 旧版本无法理解新数据库时必须停止归档写入并提示版本不兼容。
- 永久清理数据库必须由管理员单独确认，不得由卸载脚本默认执行。
- 发布包必须提供数据库备份、校验和恢复说明。

## 15. 待技术设计确认

以下项目不阻塞产品语义，但必须在编码前通过技术设计评审：

1. 目标机持久路径、overlay 可用空间和写入寿命。
2. SQLite/替代存储方案及 OpenWrt 包依赖增量。
3. sysupgrade 默认是否包含正文数据库，以及相应隐私提示。
4. 任务状态持久化与 daemon 重启恢复机制。
5. `selection_token` 快照实现和最大筛选结果规模。
6. 本地回收站自动清理的定时机制。
